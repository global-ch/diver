# Security Policy

## Reporting Security Vulnerabilities

If you discover a security vulnerability in this project, please report it responsibly. We take security seriously and appreciate your help in keeping this project safe.

### How to Report a Vulnerability

**Do not** open a public GitHub issue for security vulnerabilities.

Instead, please report the vulnerability by:
1. **Emailing us** with details about the vulnerability
2. **Including**:
   - Description of the vulnerability
   - Steps to reproduce (if applicable)
   - Potential impact
   - Your contact information
   - Suggested fix (if you have one)

### Response Timeline

- **Initial Response**: Within 48 hours
- **Assessment**: 5-7 business days
- **Fix/Patch**: As soon as possible
- **Public Disclosure**: Coordinated after patch is available

## Security Best Practices for Users

### For Divers Using This Content
- Verify all safety information with official certification organizations
- Never dive alone - always use the buddy system
- Follow all safety procedures outlined in your training
- Consult with qualified instructors and medical professionals
- Keep diving knowledge current with regular practice and education
- Use maintained and properly serviced equipment

### For Contributors
- Do not include sensitive personal information in issues or pull requests
- Review all content for accuracy, especially safety-related material
- Verify medical/health information with reputable sources
- Ensure all contributions comply with our Code of Conduct

## Vulnerability Response

### Types of Vulnerabilities We Address
- Broken links or outdated information
- Inaccurate safety procedures
- Missing important disclaimers
- Potentially harmful misinformation

### NOT Vulnerabilities
- Typos or minor grammar errors (can suggest edits)
- Design or layout issues (submit feature requests)
- Personal opinions or legitimate disagreements (discuss respectfully)
